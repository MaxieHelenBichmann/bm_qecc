("big grid" = same suite as in thesis_protoypes, aka like n=3...47)
("parameter setting" = n,k)

Implementation split: the five scripts in this directory collect shared raw
data under `paper/data/collected/`. The six scripts under `paper/experiments/`
perform the figure-specific selection and aggregation described below. In
particular, A4/A5/A6 reuse complete algorithm files, and A3 selects its backend
per parameter setting from those same files.

# A1 Rejection-rate figure
- for the relevant invariants (signatures, linear depdendecies, local invariant) which negative stb and css cases (generated by *_codes_independent_candidate, verified with SAT or other quick backend procedure, only actually ineq instances are kept) they actually reject in a big grid
- 10 randomized ineq instances per parameter setting, final result value nr of how many of these 10 were rejected
- no runtime measurement
- also compute for each invariant individually, as well as for one eq-notion combined, what percentage of instances are rejected (those are then just numbers that are outputted along the actual data)

# A2 Signature transformation-space
- for both signatures in pm_css and pm_stb compute this metric for all cases (pos and neg, important here that the signatures MATCH) on a big grid: (sum |s_i|^2)/n^2 where s_i are the equivalence classes in which the signature groups the qubits
- 10 randomized instances per parameter setting, final result value is the mean, also record stddev
- no runtime measurement

# A3 Relative preprocessing-runtime
- for linear dep on stb and css codes (pos and neg instances), signatures on css and stb (pos and neg instances), loc invariant on stb (pos and neg instances)
- take the best fully successful backend for each problem and parameter setting
- compute value T_invariant / T_backend on a big grid from the explicit invariant timings and shared algorithm statistics
- runtime measurement
- timeout 5400s, memory limit 13GiB
- 5 randomized instances per parameter setting, final result value is the mean, also record stddev 

# A4 representation vs search cost
- essentially same benchmarks as the thesis prototype for pm_stb_graph_iso, lc_stb_graph_iso for a big grid
- pos and neg instances
- timeout 5400s, memory limit 13GiB
- 10 randomized instances per parameter setting, final result value is the mean, also record stddev, just simply as in statistics

# A5 winners
- essentially same benchmarks as the thesis prototypes for all prototypes for pm_stb (not automophisms tho), pm_css, lc_stb
- pos and neg instances
- timeout 5400s, memory limit 13GiB
- 10 randomized instances per parameter setting, final result value is the mean, also record stddev, just simply as in statistics

# A6 sat and css
- essentially same benchmarks as the thesis prototype for pm_stb_sat (on stb inputs), pm_stb_sat (on css inputs), pm_css_sat (on css inputs) for a big grid
- pos and neg instances
- timeout 5400s, memory limit 13GiB
